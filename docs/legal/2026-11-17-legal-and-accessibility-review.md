# John's legal and accessibility list, answered with evidence (AH-178)

**Date:** 2026-11-17 · **Pod 2**, alongside Pod 1's AH-176 · **Base:** origin/main `3d7fb7f`
**Machine:** YURILOVER (the laptop), Python 3.15.2, Node 26.7.0

John asked for two things in one request: the fifteen ways a vibe-coded app gets hacked, and about twenty things a
site needs so it does not get sued. Pod 1 took the security half under AH-176 and answered it in
`docs/security-and-launch-checklist.md`. This file is the other half, plus the eight attack stories Pod 1 handed over
because they land on parts of the product Pod 1 was not holding.

**The rule this file follows is the repo's own, from `backend/tests/test_fix.py:642`:** a page may not make a
comfortable absolute claim that nothing in code enforces. That test forbids the phrases *"any other third party"* and
*"never transmitted"* on any privacy page, because the page once said nothing was sent to a third party while the relay
runs on Cloudflare. So nothing below is answered with reassurance. Every PRESENT names a file and line. Every N/A says
why, tied to this architecture, and what plays that role instead. Everything that could not be checked on this machine
says so, rather than being written as green.

**What decides a lot of these:** Arcas has no accounts, no database, no sessions, no passwords, no admin surface, no
payments and no upload route. The engine is one user's own PC on `127.0.0.1`. The website is static files on GitHub
Pages with no server code and no form that posts anywhere. The only server of ours online is the relay.

## The eight attack stories Pod 1 handed over

Pod 1 answered keys, rate limiting, XSS, admin routes, git history, the unmetered AI endpoint and the database
question in `docs/security-and-launch-checklist.md`. These eight were handed to this pod.

| John's story | Verdict | Evidence |
|---|---|---|
| "I changed the number in your URL" (IDOR) | **Does not apply** | Every identifier indexes **the caller's own request body**, never someone else's record: `server.py` bounds `row_index` by `len(body["rows"])`, and bounds each change's column by the width the caller sent. `/scan`'s `start_row` and `sheet` are written as CSV field *values*, never as a path, and the CSV path is fixed in code. The website calls `releases/latest`, with no id in any URL. There is no shared store for an id to reach into. |
| "I made myself an admin when I signed up" | **Does not apply, and there is nothing to become** | No signup, accounts, roles, sessions or cookies exist. On the engine the Origin and Host check **is** the whole authorisation (`own_panel_only`), with no credential at all. On the relay an invite code is the only credential and it carries **no privilege level**: it selects a different model and a different daily bucket, nothing more. `docs/security/SECURITY-LESSONS.md` G1 writes down that an admin surface may never be added, and CLAUDE.md repeats it. |
| "I changed the price before checkout" | **Does not apply** | A grep for stripe, checkout, price, paid, subscription, webhook, purchase, billing, invoice and coupon across the whole repo returns **no payment code at all** — every hit is spreadsheet column vocabulary. The client does pick its tier, by whether an `Authorization` header is present, but the invite tier needs a 144-bit code and the public tier is open to everyone anyway, so there is no upgrade to take. Model, key and `max_tokens` are set by the relay and ignored from the body. |
| "I sent your app a fake payment succeeded" | **No path to extra answers** | There is no inbound webhook or unauthenticated callback: the relay routes `POST /fix` alone. The nearest equivalent is the quota refund when Google says it is busy for the minute, probed directly by Pod 1 and read by this pod: a 200 is never refunded; a refund never returns more than was taken; it cannot be credited to another caller, since the keys are server-derived and never reassigned; and no client-controlled field decides it. **What it does allow is extra ATTEMPTS, not extra answers** — the day cap bounds answers, so while Google is busy a caller can keep calling without spending its day. Availability only, ticketed as AH-179. One brittleness worth knowing: the per-day/per-minute split is a `/perday/i` substring of Google's own error text, so a renamed metric would change the behaviour silently. |
| "I clicked redeem 100 times at once" | **Held, with the dependency stated** | The relay's counter is **not** internally atomic — get, check and put with awaits between — and its correctness rests entirely on the Durable Object input gate, which the code states at `relay/worker.js:188` and which both harnesses supply themselves, so the tests prove the caps hold *given* the gate. `relay/load.mjs` fires 2,200 at once and requires exactly the caps through and no 5xx. The engine takes one AI call at a time. The pane has four independent guards against a double-click: a one-action-at-a-time flag, `oneClickEach` dropping any click with `event.detail > 1`, an `applyFix` that is idempotent per row, and a re-read that writes nothing if the row changed since the scan. **No test double-clicks Accept itself**, though the same two shared guards are exercised by the Undo, Dismiss and Forget double-click tests. |
| "I ordered -1 items and got a refund" | **Held except one field, fixed here** | `strength` must be an int 0–10; limits reject NaN and infinities and enforce low ≤ high; `/scan`'s `start_row` is bounded by the real sheet; `/fix`'s `nat` rejects negatives, floats and bools; the pane clamps the slider on read; the relay's refunds cannot go below zero. **The gap: `/fix`'s `start_row` had no upper bound** while `/scan`'s did, and the checklist claimed otherwise. It was fail-closed downstream, so a missing guard rather than an exploit — fixed at the boundary where every other field is checked, with a test at the limit and one past it, and the spec's `maximum` added so the fuzzer generates against it. Pod 1 corrected the document half in the same hour. |
| "I brute forced your 6-digit login code" | **Entropy and storage held; the rate limit was the gap, now fixed by Pod 1** | There is no login code. The nearest thing is a relay invite: `inv_` plus 18 random bytes, **144 bits**, stored only as its SHA-256 so even the relay's settings reveal nobody's code. Guessing it is not the attack. **The real finding is that the wrong-guess 401 was returned before the per-minute limit was ever asked**, so guesses — and every other cheap refusal — were unlimited and free, and each still spends one Workers request against an account-wide daily allowance of 100,000. Handed to Pod 1, whose file it is. They routed all seven pre-counter refusals through one helper keyed in a separate `"no:"` bucket, so a garbage flood is metered from request one and cannot eat a real caller's minute; guard-map row 74, mutants `relay-burst-preauth-loosen` and `relay-burst-bucket-tighten` both killed. |
| "I uploaded a file that isn't a photo" | **No upload route; a real gap on hostile FILES, fixed here** | Nothing reads `request.files` or any path from a body; `/key` writes two fixed filenames behind a regex; static files go through Werkzeug's `safe_join`. The write side is formula-inert and tested in both directions. **Two real gaps on the read path, both fixed here:** `engine/load.py` had no cap on a workbook's decompressed size, so a small `.xlsx` that expands to gigabytes had nothing stopping it; and `openpyxl` hardens its XML parser only when `defusedxml` is importable, which was in neither the runtime dependencies nor the `exe` extra — so **the Arcas.exe users run parsed untrusted workbook XML with a weaker stack than every test machine**, and `constraints.txt` pinning the package did not help, because a constraint caps a version without installing anything. |

## What was fixed in this ticket

Every item below went red before and green after, in `backend/tests/test_legal_pages.py` (10 checks). The red was
measured against a pristine `origin/main` worktree rather than by reverting files, so the before state is the real
shipped one: **9 of 10 failed on pristine main, and the tenth failed once the notices file was removed.**

1. **The privacy policy said live analytics had not started.** Fixed in all three twins plus the summary table and the website section.
2. **The privacy policy never named the rights a reader has.** Added access, rectification, erasure, restriction, portability and objection in plain words, with the lawful basis, the retention position, how to ask, and the right to complain to a supervisory authority — in the twinned `rights` section, so the pane and `PRIVACY.md` carry it too.
3. **No cookie policy.** Written as a statement in the website-only section, with the reason there is no banner.
4. **No refund policy.** Written into the terms.
5. **A blanket liability exclusion.** Given a savings clause, because an unqualified "not liable for any loss" is void in part against consumers (UK CRA 2015 s.65, Directive 93/13).
6. **The crisis path was not in the terms.** Stated as a signpost and explicitly not a crisis service.
7. **The Fairness check read like a discrimination clearance.** Now says it is a data-quality signal and not a legal or compliance finding.
8. **A new-tab link warned screen readers only.** Now says so in the link text.
9. **No accessibility statement.** Added, claiming no more than is actually checked, with a Known limits row and a route to report a barrier.
10. **No third-party notices for what `Arcas.exe` redistributes.** `THIRD-PARTY-NOTICES.md` added, covering the ten runtime packages and CPython, office.js, the OFL font, the CC BY 4.0 data and the artwork — with a test that fails if a new runtime dependency has no row.

Plus, from the attack stories, in `backend/tests/test_hostile_input.py`: the `defusedxml` divergence, the workbook
unpacked-size ceiling, `/fix`'s unbounded `start_row`, and `keep_invite` sealing an invite of any shape.

## Debt this ticket leaves, deliberately

The repo's rule is that a new or changed guard adds its loosen and tighten mutants to `tools/mutations.json` in the
same commit, with a row in `docs/security/GUARD-MAP.md`. **Four guards added here have neither**, because both files
are held by AH-176 and must not be touched by a second pod:

- the workbook unpacked-size ceiling (`engine/load.py`)
- `defusedxml` being importable, which is what makes `openpyxl.xml.DEFUSEDXML` true in the shipped exe
- `/fix`'s `start_row` upper bound (`server.py`)
- `keep_invite`'s invite-shape check (`app.py`)

These are real outstanding debt, not oversights. They belong in the commit that lands after AH-176, and the layer-5
and layer-9 rows of `CLAUDE.md`'s table want the same update.

- **AH-181, the largest legal exposure in the project.** The relay's public tier gives any stranger Gemini calls on John's personal key with no credential, no identity and no acceptance of any terms. Google's current terms, fetched and quoted on 2026-11-17 from `https://aistudio.google.com/docs/terms`: *"Use of Google AI Studio and Gemini API is for developers building with Google AI models for professional or business purposes, not for consumer use."* and, for the unpaid tier, *"Google uses the content you submit to the Services and any generated responses to provide, improve, and develop Google products and services and machine learning technologies"*. A free Excel add-in for anyone is consumer use, and strangers' sheet fragments enter Google's improvement pipeline under John's key, which puts the data-protection accountability for them on him. The sanction is key, project or **Google account** suspension. This is not a defect: it is a design John chose in AH-151, so only John may change it. ## Not run, or not verified, on this machine

- **The browser half of `tools/test_site.mjs`** — contrast across 51 states, 24 px targets, the keyboard flows — needs Playwright and Chromium. It runs in CI only, and has never run on either of John's own machines.
- **The static half of `tools/test_site.mjs` cannot be run green on any Windows checkout at all.** It fails at `:404` on correct data, because the field-id regex is anchored on a bare newline and a Windows checkout is CRLF. Ticketed as AH-180 with the root fix. The run stops at the first failure, so how many more assertions in that file are CRLF-fragile is unknown. **This is one root pattern that produced five separate false results on 2026-11-17 alone:** this one; `tools/mutate.py` printing SURVIVED for mutants it never planted (LF in `mutations.json` against a CRLF tree, Pod 1); two mutants surviving vacuously because their only tests are `skipif(os.name == "nt")` and `mutate.py` reads pytest's exit code 0 as a pass (Pod 1); and two in this ticket's own new tests, where `read_text()` and `write_text()` each translated a deliberate CRLF and failed an assertion on byte-correct code. Nothing in the repo normalises line endings, and the existing `.gitattributes` governs only `*.bat` — which must stay `eol=crlf`, because an invite kit is `git archive HEAD` and `install.bat` depends on it.
- **Two pre-existing failures in `test_fix.py` on Windows**, unrelated to this ticket: the tests expect a plain-text key file, while on Windows the key is DPAPI-sealed (AH-104). Already fixed in Pod 1's unlanded tree.
- **Whether GoatCounter's own server derives a per-visitor hash from IP and user agent.** It decides whether the footer's "No tracking of you" is accurate on the processor's side. The footer was kept as it stands, on the reasoning that no identifier, cookie, fingerprint or cross-page join exists in our code, and that the claim which would fail a strict reading — "nothing is sent to anyone" — is made nowhere, since `site/privacy.html:140` names GoatCounter and says it sees the IP. Recorded as a judgement call; Pod 1 initially read it the other way and then agreed.
- **`site/assets/og-card.png`'s artwork against its `og:image:alt`**, which claims a strapline appearing in no page copy.
- **`site/cases.html`'s claim** that every other Elton John song in the table is from 1970 to 1975, against the committed fixture.
- **Any trademark register position for "Arcas".** No clearance search is recorded anywhere in the repo. A USPTO and EUIPO search in the software classes is ten minutes and is currently a blind spot.
